# Data Model: User Account Management

## ApplicationUser

Extends the identity user type with application-owned profile and lifecycle fields.
The entity maps to the ERD's physical `Users` table. ASP.NET Core Identity still manages password
hashes and supporting role, claim, login, and token tables.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| Id | GUID | Yes | Primary key generated by the application |
| DisplayName | string | Yes | Trimmed; 2-50 characters |
| Email | string | Yes | Valid email; case-insensitive unique identity |
| NormalizedEmail | string | Yes | Identity-managed uppercase normalized value; unique index |
| PasswordHash | string | Yes | Identity-managed; never returned in API models |
| IsActive | boolean | Yes | Defaults to true |
| CreatedAtUtc | timestamp | Yes | Set once at registration |
| DeactivatedAtUtc | timestamp | No | Set when an administrator deactivates the account |
| SecurityStamp | string | Yes | Identity-managed; never returned in API models |

Roles are stored through the standard identity role and user-role relationship. Supported role
names are `Author` and `Admin`. Public registration always assigns `Author`.

### Validation invariants

- `DisplayName` is normalized before validation and persistence.
- `NormalizedEmail` uniquely identifies the account regardless of email casing.
- `IsActive = true` requires `DeactivatedAtUtc = null`.
- `IsActive = false` requires `DeactivatedAtUtc` to contain the deactivation time.
- Password input is 8-128 characters and is passed to Identity; plaintext is never persisted.

### State transitions

```text
Not registered -> Active Author       registration
Active User    -> Active User         profile or password update
Active User    -> Inactive User       administrator deactivation
Inactive User  -> Inactive User       repeated deactivation (idempotent)
```

Reactivation and permanent deletion are outside this feature.

## IdentityRole

Uses the standard identity role entity with a GUID key.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| Id | GUID | Yes | Primary key |
| Name | string | Yes | `Author` or `Admin` |
| NormalizedName | string | Yes | Unique normalized role name |

## UserDeactivation

Records the administrative action separately from the user's current lifecycle fields.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| Id | GUID | Yes | Primary key |
| TargetUserId | GUID | Yes | Foreign key to the deactivated user; delete restricted |
| AdminUserId | GUID | Yes | Foreign key to the acting administrator; delete restricted |
| DeactivatedAtUtc | timestamp | Yes | UTC action timestamp |

### Relationships

- One user can be the target of zero or more deactivation records.
- One administrator can create zero or more deactivation records.
- A user cannot be physically deleted while referenced by a deactivation record.
- Future retrospective-to-user relationships use restricted deletion so author attribution is
  retained.

## API projections

### UserResponse

Contains `id`, `displayName`, `email`, `role`, `isActive`, `createdAtUtc`, and
`deactivatedAtUtc`. It never contains credential or identity-internal fields.

### AuthResponse

Contains the access token, token expiration time, and safe `UserResponse` identity data.

### PagedUsersResponse

Contains `items`, `page`, `pageSize`, and `totalCount`. The page size cannot exceed 100.
